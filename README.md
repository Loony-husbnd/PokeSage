# PokeSage

포켓몬 챔피언스(싱글, 현재 규정 Reg M-C)에서 **매 턴 최선수를 추천**하고 **기보를 기록**하는 도구.
후보 행동마다 Showdown 시뮬레이터로 수백~수천 판을 끝까지 굴려 승률을 비교한다.

## 구조

| 위치 | 역할 |
|---|---|
| `engine/export_data.js` | Showdown 포챔스 모드에서 종·기술·도구·특성을 JSON(`data/champions/`)으로 내보낸다. **사용 가능 여부는 Showdown 팀 검증기의 판정**을 그대로 쓴다. |
| `engine/world.js` | 상태(HP%·상태이상·랭크·날씨·필드·구애 고정·메가진화 여부)를 Showdown 배틀에 덮어써 임의 시점의 배틀을 만든다. |
| `engine/belief.js` | 상대의 숨은 정보(특성·도구·기술·스탯 포인트·성격)를 추정한다. 관측한 값은 고정하고 나머지를 표본 추출한다. 미공개 선출 포켓몬은 팀 프리뷰 6마리에서 뽑는다. |
| `engine/policy.js` | 롤아웃용 휴리스틱 정책(대미지 어림, 변화기 가치, 교체 상성, 메가진화). |
| `engine/worker.js` | 줄 단위 JSON 서버: `validate`, `recommend`. 관측 일치 필터와 후보별 롤아웃을 수행한다. |
| `pokesage/engine.py` | Node 워커 풀. 세계를 코어에 나눠 병렬로 굴리고 승률·95% 구간을 합산한다. |
| `pokesage/cli.py` | 객관식/입력칸 폼. 팀 구성(검증기로 규정 확인) → 매 턴 상태 입력 → 추천 → 결과 입력. |

## 실행

```bash
bash engine/setup.sh        # Showdown 고정 커밋을 받아 빌드 (처음 한 번, 약 1~2분)
python -m pokesage          # 대화형 실행  (--worlds 300 --workers 4)
python -m pytest -q         # 테스트
```

Google Colab: `colab/PokeSage.ipynb` 를 열어 위에서부터 실행한다.

## 매 턴 흐름

1. 상태 입력: 내/상대 선두, HP%, 상태이상, 랭크, 날씨·필드·사이드 상태. (직전 값은 첫 선택지 "유지")
2. 추천: 후보 행동(기술, 메가진화 변형, 교체)별 승률과 95% 구간. 1·2순위 구간이 겹치면 경고한다.
3. 결과 입력: 내가 한 행동, 상대 행동, 선공 쪽, 새로 드러난 정보(특성/도구/메가).
4. **다음 턴에 관측이 반영된다**: 추정한 상대 세트로 지난 턴을 시뮬레이터에서 다시 굴려, 관측한 행동 순서와 HP 변화(±2%)에 맞지 않는 세계는 버린다. 즉 "내 기술이 이만큼 들어갔다 / 상대가 먼저 움직였다"가 상대의 스탯 포인트·성격·도구 추정을 좁힌다.

## 포챔스 데이터 기준 (현재 버전)

- 기준 커밋: `engine/SHOWDOWN_COMMIT` (smogon/pokemon-showdown, 2026-11-16, `champions` 모드, Reg M-C).
- 능력치: 스탯 포인트(SP) — 스탯당 최대 32, 합계 66. Lv.50 `종족값 + SP + 20` (HP는 `+ 75`), 성격 ±10%. Showdown 실제 계산과 일치하는지 테스트가 교차 검증한다.
- 규칙: 6마리 중 3마리 선출, 종 중복 금지, 도구 중복 금지, 환상·준전설 제외.
- 사용 가능 수: 종 292, 기술 515, 도구 166(메가스톤 83 포함), 특성 317. 예: 돌격조끼·구애머리띠는 **없음**, 구애스카프·기합의띠·생명의구슬은 **있음**. 종별 습득 기술도 Showdown 학습 정보 기준이다.
- 게임이 업데이트되면: `engine/SHOWDOWN_COMMIT` 를 새 커밋으로 바꾸고 `bash engine/setup.sh && node engine/export_data.js data/champions` 를 실행한다. 새 항목은 검증기 판정에 따라 자동으로 반영/제외된다. (`Floette-Eternal` 은 검증용 개체값 조건 때문에 목록에서 빠져 있다.)
- 한글 이름은 `data/ko_names.json` (PokeAPI 한국어 이름, Pokemon-Seal-Archive 의 이름표를 변환). 기술명 등이 실제 게임 표기와 다를 수 있다.

## 성능과 GPU

- 측정(4코어 샌드박스): 약 230~450판/초. 세계 1,000개(후보 5개 = 5,000판)에 약 11초. Colab 기본 CPU(2코어)에서는 절반 이하로 보면 된다.
- **GPU는 이 구조에서 속도를 거의 높이지 못한다.** 시뮬레이터는 분기가 많은 CPU 작업이고, 병렬화는 코어 수(`--workers`)에 비례한다. GPU가 의미 있는 경우는 두 가지다: ① 대미지 계산을 텐서로 일괄 처리하는 단순화 엔진(특성·도구가 시뮬레이터와 달라진다), ② 시뮬레이션 결과로 가치망을 학습해 롤아웃을 신경망 평가로 대체. 현재는 구현하지 않았고, 필요하면 ②를 추가하는 쪽을 권한다(시뮬레이터가 학습 데이터를 생성).

## 알려진 한계

- **승률은 상대 비교용이다.** 상대를 "추정한 세트 + 휴리스틱 정책"으로 가정하므로 절대 수치(80~97%)는 부풀려진다. 행동 간 차이와 구간 겹침을 보라.
- 방어·대리처럼 한 턴을 쉬는 행동은 유리하게 평가되는 편향이 있다(경고 문구를 표시한다).
- 첫 수만 후보별로 비교하고 이후는 같은 휴리스틱 정책으로 이어 간다. 상대의 이번 턴 선택은 정책에서 샘플링한다(동시 선택 게임을 정밀하게 풀지 않음).
- 상태 입력에 없는 것: 혼란·대리·방어 연속 사용·도발 등 휘발성 상태, 필드 남은 턴(기본 지속 턴으로 가정).
- 더블 배틀은 미지원. 오른쪽 규칙은 싱글 Reg M-C 기준이다.
